API Key 安全使用指南：防盗刷与泄露应急处理

API Key 就是你账户的"钱包 + 身份凭证"。一旦泄露，别人可以直接用你的余额调用模型，甚至读取你提交的数据。本文给出一套实用的 Key 安全规范。

一、Key 泄露的常见途径

  • 硬编码到代码：把 Key 直接写进源码并 push 到公开仓库，是最常见的泄露方式；
  • 前端暴露：把 Key 放在网页 JS 里，任何人按 F12 都能看到；
  • 截图与分享：在群聊、教程截图里带出了完整 Key；
  • 第三方工具：使用来源不明的客户端或插件，Key 被悄悄上传；
  • 日志与报错：把带 Key 的请求日志发给了别人。

二、日常防护措施

  1. Key 只放在服务端环境变量或密钥管理服务里，绝不进前端和代码仓库；
  2. 为不同项目、不同成员分配独立的子 Key，便于隔离与追溯；
  3. 给子 Key 设置额度上限、模型白名单与过期时间；
  4. 在仓库中配置 .gitignore，并对历史提交做密钥扫描；
  5. 定期轮换 Key，尤其是成员离职后立即更换。

三、发现泄露后的应急处理

  1. 立即撤销：到中转站后台删除或禁用该 Key，这是止损第一步；
  2. 检查账单：查看异常调用记录，确认损失范围；
  3. 重新签发：生成新 Key 并更新到所有使用方；
  4. 修正源头：删掉泄露的代码/截图，撤销历史提交中的密钥；
  5. 开启告警：设置余额与调用量告警，防止再次被刷。

四、团队场景的密钥管理

团队应避免"一个 Key 大家共用"。正确做法是：每人/每个服务一个子 Key，由管理员统一在后台管理权限与额度，定期导出用量报表核对。更多团队管理方法见团队版中转站指南。
